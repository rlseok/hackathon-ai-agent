# 02. 작업 기록 (2026-10-14 ~ 10-16)

데스크톱 환경: Windows 11, NVIDIA GTX 1060 6GB, Python 3.14, PyTorch 2.14.1+cu126, Ultralytics 8.4.177

각 작업마다 **무엇을 했는지 / 왜 했는지 / 결과** 를 적었다.

## 작업 1. 학습 환경 구축

- **한 것:** 가상환경(`C:\Users\연구실\.venv`) 생성, PyTorch(CUDA 12.6 빌드) + Ultralytics 설치.
- **왜:** GTX 1060 은 오래된 Pascal 세대라 최신 CUDA 12.8 이상 빌드에서 지원이 빠졌을 수 있어 cu126 빌드를 사용했다.
- **겪은 문제:**
  - PowerShell 실행 정책 때문에 `Activate.ps1` 실행 불가 → `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 또는 `-ExecutionPolicy Bypass` 로 해결.
  - 명령을 홈 폴더에서 실행해 상대경로(`data/...`)를 못 찾는 오류가 반복 → 어느 위치에서 실행해도 동작하는 `.ps1` 스크립트로 해결 (`tools/ps1/`).
  - 학습 도중 OneDrive 바탕화면 백업을 끄면서 폴더가 `OneDrive\Desktop` → `Desktop` 으로 이동, 이미지 경로가 깨져 학습 중단 → `data.yaml` 경로 수정, 라벨 캐시 삭제 후 재학습.

## 작업 2. PCB 데이터셋 분석

- **원본:** Roboflow `obj-detection-pcb-defects-yolov8 v3` (바탕화면 `PCB_dataset`), 9,666장, 640×640, 결함 8종, CC BY 4.0.
- **발견한 문제와 의미:**

| 문제 | 내용 | 왜 중요한가 |
|---|---|---|
| **분할 간 데이터 누수** | 원본 보드 사진 1장을 최대 15조각으로 잘라 만든 구조인데, 같은 원본의 조각이 train/valid/test 에 흩어져 있었다 (valid 원본 693개 중 659개가 train 에도 존재) | 이대로 학습하면 평가 점수가 실제보다 높게 나와 실제 사진에서 성능이 크게 떨어질 수 있다 |
| 정상 이미지 0장 | 모든 이미지에 결함이 있다 | 정상 보드 오탐률을 측정할 수 없다 |
| 결함이 매우 작음 | 박스 면적 중앙값이 이미지의 0.06% | 큰 실사진을 그대로 640 으로 줄이면 결함이 사라진다 → 잘라서 추론 또는 고해상도 추론 필요 |
| 폴리곤 라벨 5줄 | 박스 형식이 아닌 라벨 | 박스로 변환 |

## 작업 3. PCB 데이터 재분할 → `pcb_v2`

- **한 것:** `tools/resplit.py` — 원본 사진 이름(예: `08_short_05`) 기준으로 묶어 같은 원본의 조각은 반드시 같은 분할에 들어가게 했다. 클래스 비율이 80/10/10 이 되도록 배정.
- **결과:** train 7,693 / val 993 / test 980 장, 원본 그룹 875 / 259 / 255 개, 8개 클래스 모두 80/10/10.
- **왜:** 누수 제거. 이후 모든 PCB 평가 수치는 처음 보는 원본 사진 기준이라 실제 성능에 가깝다.

## 작업 4. 라벨 체계와 지식베이스 설계

- **한 것:** YOLO 클래스 8개는 그대로 두고, 에이전트용 정보는 `knowledge/defect_taxonomy_pcb.yaml` 로 분리.
  - 클래스별: 한글명, 상위 그룹(회로 단절 / 잔여 동박 / 홀 불량 / 표면), 심각도(critical/major/minor), 설명, 원인 후보, 즉시 조치·점검·재발 방지
  - 판정 기준값(0.25 / 0.5), 상황별 동작(정상 / 재검 / 불량 / 복합 결함 / 동일 위치 반복)
- **왜:** 해커톤 STEP 3~4(원인·조치)를 모델 재학습 없이 관리하기 위해. 주최 측 불량 유형 정의서가 오면 이 파일만 교체.
- **주의:** 일반적인 PCB 제조 지식 기반 **초안**이다. 배선 폭·간격 감소율 같은 수치 기준은 고객사 기준서 / IPC-A-600 으로 확인해 채워야 한다.
- **결정:** 정상 이미지를 추가로 구하는 작업(PKU-Market-PCB 템플릿)은 비용 대비 효과가 낮아 보류. "검출 없음 = 정상" 판정은 그대로 쓰고, 실제 사진으로 오탐을 확인한 뒤 필요하면 추가하기로 했다.

## 작업 5. PCB 모델 학습 (채택 모델)

- **설정:** `yolo11s.pt`, 100 에폭, imgsz 640, batch 8, GTX 1060 에서 10.3 시간.
- **왜 yolo11s:** 결함이 작아 nano(n) 보다 한 단계 큰 small(s) 을 선택. 6GB GPU 에서 batch 8 로 약 2.8GB 사용.
- **결과 (test 980장):** mAP50 0.886, Precision 0.911, Recall 0.868 → 03 문서.
- **파일:** `models/pcb_v2_yolo11s.pt`, 기록 `results/pcb/train_v2/`, 평가 `results/pcb/test_eval_v2/`

## 작업 6. 추가 데이터로 스크래치 개선 시도 (미채택)

- **배경:** 스크래치 인식이 안 되는 경우가 있어 Roboflow `PCB_Project v8` (4,976장, train 만 있음) 을 추가.
- **검수 결과:**
  - 클래스 순서가 기존과 달랐다 (예: 새 데이터 0번 = Pinhole, 기존 0번 = falsecopper) → 이름 기준 재매핑 (`tools/merge_extra.py`).
  - 새 데이터는 **기존과 같은 원본 PCB 사진 1,384장**에 다른 증강(416 리사이즈, 반전, 90도 회전)을 적용한 것이었다 → 기존 val/test 원본과 겹치는 1,837장은 제외하고 train 원본만 3,136장 추가 (누수 방지).
  - Scratch 라벨은 기존과 같은 방식(가는 긁힘 선을 큰 박스로 감쌈)임을 이미지로 확인. 홀 누락 라벨이 빠진 1장(증강 3개)은 제외.
- **학습:** 기존 best 모델에서 이어서 60 에폭 (8.6 시간).
- **결과:** test mAP50 0.886 → 0.875, scratch mAP50 0.905 → 0.881, missinghole 0.793 → 0.663 으로 **오히려 하락** → **미채택, v2 유지.**
- **교훈:** 같은 원본 사진의 증강본은 새 정보가 적다. 실제 사진에서 못 잡는 문제는 **비슷한 실제 사진을 라벨링해 추가**해야 풀린다.

## 작업 7. 금속 표면 결함 데이터셋 정리 → `msdd_v1`

- **원본:** Roboflow `MSDD-Prompt-Learning v9`, 1,495장, 512×512, CC BY 4.0. zip 안에 동일한 `data.yaml` 이 3개 중복되어 있었음 (내용 동일, 하나만 사용).
- **발견한 것:**

| 발견 | 처리 | 이유 |
|---|---|---|
| 원형 금속 부품 299개를 각각 5방향 촬영 (CAP2/3, CAP4 상하좌우) | **부품 단위로 묶어** 재분할 | 같은 부품의 다른 각도 사진이 분할을 넘으면 누수 |
| 원래 분할이 train 240 / valid 85 / test 1,170 으로 거꾸로 | 80/10/10 으로 재분할 | 학습 데이터 확보 |
| **"Normal" 클래스 = 부품 전체 윤곽 폴리곤** (이미지 면적 약 98%) | **클래스 제거** → Normal 만 있던 이미지는 빈 라벨(정상 이미지) | "검출 없음 = 정상" 판정과 충돌하기 때문. 덕분에 정상 이미지 244장 확보 |
| 모든 라벨이 폴리곤(윤곽선) | **세그멘테이션 모델**로 학습 | 가늘고 휘어진 스크래치를 모양대로 표시 가능, 결함 면적 계산 가능 (향후 크기 기준 판정) |
| 파일명의 OK/NG 와 라벨이 불일치 (OK 인데 결함 라벨 487장) | 학습에 쓰지 않고 `results/msdd/meta.csv` 에 기록 | 검사자 판정은 "결함이 있어도 허용 범위면 OK" 로 보임 → 향후 **유형·크기 → OK/NG 규칙** 근거 데이터 (해커톤 TOPIC 02 와 연결) |

- **결과:** train 1,195 / val 150 / test 150 장 (부품 239 / 30 / 30), 클래스 6개 (Dark Spot, Fold, Oxidation, Porosity, Scratch, Stain). 대부분 80/10/10 이고 Scratch·Stain 의 test 비율만 7~8%.
- **스크립트:** `tools/prepare_msdd.py` (부품 단위 무작위 배정을 5,000회 시도해 클래스 비율이 가장 고른 안을 선택)

## 작업 8. 금속 표면 모델 학습

- **설정:** `yolo11s-seg.pt`, 150 에폭, imgsz 512, batch 8, patience 40, 약 2.2 시간.
- **결과 (test 150장):** 사진 단위 판정 정확도 92.7% (신뢰도 0.25), mask mAP50 0.564 → 03 문서.
