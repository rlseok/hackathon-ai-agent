## 1. 전체 구조

```
[작업자] 사진 업로드 (+ 품번·공정 정보)
   │
   ▼
① 본다     [코드] YOLO 추론 ─ 결함 위치·유형·신뢰도, 결함 확대 이미지(crop)
   │                         금속 모델이면 마스크 면적도 계산
   ▼
③ 판단한다  [코드] 판정 규칙 ─ 정상 / 재검 필요 / 불량   (taxonomy 의 judgment 기준값)
   │              복합 결함이면 심각도 최고 유형을 대표로
   ▼
② 찾는다    [코드] 지식 조회 ─ 유형별 한글명·심각도·원인 후보·조치 (taxonomy YAML)
   │              (확장) 과거 불량 이력·기준서 RAG 검색
   ▼
④ 작성한다  [Qwen] 결함 특징 설명, 원인·조치 문장 정리 ─ 위에서 넘긴 사실만 근거로
   │
   ▼
[화면] 작업자 확인 (Human-in-the-loop) ─ 유형 수정, 판정 확정/기각, 문장 수정
   │
   ▼
[코드] 보고서 생성 ─ 사진 + 표시 이미지 + 유형·원인·조치 → Word/PDF
```

**왜 이렇게 나누는가**
- 노트북용 작은 Qwen 은 긴 절차를 스스로 계획하게 하면 단계를 빼먹거나 없는 원인을 지어낸다.
- 그래서 **순서와 판정은 코드로 고정**하고, Qwen 에게는 "이 사실들로 문장을 써라" 처럼 **좁은 일**만 준다.
- 나중에 안정되면 Qwen 의 tool calling 으로 일부 단계를 넘겨도 된다 (Ollama 는 Qwen3 의 도구 호출을 지원).

## 2. 개발 순서 (권장)

| 순서 | 작업 | 산출물 | 완료 기준 |
|---|---|---|---|
| 1 | **검출 + 판정 함수** | `agent/detect.py` | 사진 → 판정·결함 목록 JSON |
| 2 | **지식 조회** | `agent/knowledge.py` | 유형명 → 원인·조치 딕셔너리 |
| 3 | **Qwen 문장 생성** | `agent/writer.py` | 1·2 결과 → 보고서 문장 (근거 외 내용 없음) |
| 4 | **보고서 출력** | `agent/report.py` | Word 파일에 사진·표·문장 |
| 5 | **작업자 확인 화면** | `app.py` (Streamlit) | 업로드 → 결과 확인·수정 → 보고서 다운로드 |
| 6 | 금속 모델 지식베이스 | `knowledge/defect_taxonomy_msdd.yaml` | 6종 원인·조치 (현재 **없음**) |
| 7 | 부품 단위 판정 | `detect.py` 확장 | 한 부품의 여러 사진 중 하나라도 불량이면 불량 |
| 8 | (선택) 비전 LLM 보조 | `writer.py` 확장 | 결함 crop 을 Qwen-VL 에 넣어 특징 설명 |
| 9 | (선택) 다국어 보고서 | 프롬프트 | 한국어·베트남어 (해커톤 도전 포인트) |

**1~5 를 먼저 끝까지 연결**해 데모가 돌아가게 만든 뒤 6 이후를 붙이는 것이 좋다.

## 3. 코드 뼈대

아래는 출발점이다. 패키지 루트에 `agent/` 폴더를 만들어 나눠 넣으면 된다.

### 3-1. 검출 + 판정 (`agent/detect.py`)

```python
from pathlib import Path
import yaml
from ultralytics import YOLO

ROOT = Path(__file__).resolve().parents[1]
MODELS = {
    'pcb':  (ROOT / 'models/pcb_v2_yolo11s.pt', 640),
    'msdd': (ROOT / 'models/msdd_v1_yolo11s_seg.pt', 512),
}
TAXONOMY = yaml.safe_load((ROOT / 'knowledge/defect_taxonomy_pcb.yaml').read_text(encoding='utf-8'))
TH = TAXONOMY['judgment']            # conf_review 0.25, conf_reject 0.5
_cache = {}


def detect(image_path, domain='pcb', save_dir=None):
    path, imgsz = MODELS[domain]
    model = _cache.setdefault(domain, YOLO(str(path)))
    r = model.predict(str(image_path), imgsz=imgsz, conf=TH['conf_review'], verbose=False)[0]
    h, w = r.orig_shape
    defects = []
    for i, (c, conf, box) in enumerate(zip(r.boxes.cls, r.boxes.conf, r.boxes.xyxy)):
        x0, y0, x1, y1 = box.tolist()
        d = {'type': model.names[int(c)], 'conf': round(float(conf), 3),
             'box_px': [round(x0), round(y0), round(x1), round(y1)],
             'size_px': [round(x1 - x0), round(y1 - y0)],
             'position': f'{"상" if (y0 + y1) / 2 < h / 2 else "하"}{"좌" if (x0 + x1) / 2 < w / 2 else "우"}'}
        if r.masks is not None:      # 세그멘테이션: 면적 비율
            d['area_ratio'] = round(float(r.masks.data[i].sum() / r.masks.data[i].numel()), 5)
        defects.append(d)

    if not defects:
        verdict = 'normal'
    elif any(d['conf'] >= TH['conf_reject'] for d in defects):
        verdict = 'reject'
    else:
        verdict = 'review'

    marked = None
    if save_dir:
        marked = Path(save_dir) / f'{Path(image_path).stem}_marked.jpg'
        r.save(filename=str(marked))
    return {'verdict': verdict, 'defects': defects, 'marked_image': str(marked) if marked else None}
```

### 3-2. 지식 조회 (`agent/knowledge.py`)

```python
from agent.detect import TAXONOMY

SEVERITY_ORDER = {'critical': 0, 'major': 1, 'minor': 2}


def lookup(defect_types):
    """검출된 유형들 → 지식 항목 (심각도 높은 순)."""
    items = []
    for t in sorted(set(defect_types)):
        info = TAXONOMY['defects'].get(t)
        if info:
            items.append({'type': t, **info})
    return sorted(items, key=lambda x: SEVERITY_ORDER.get(x['severity'], 9))
```

### 3-3. Qwen 문장 생성 (`agent/writer.py`)

```python
import json
import ollama

MODEL = 'qwen3:8b'   # 노트북에 받은 모델 이름으로

SYSTEM = """너는 제조 품질 보고서를 작성하는 보조자다.
규칙:
1. 아래 [검출 결과]와 [지식] 에 있는 사실만 사용한다. 없는 원인·수치를 만들지 않는다.
2. 원인은 '후보'로 표현하고 단정하지 않는다.
3. 물리적 조치(격리, 수리, 폐기)는 '작업자 확인 후 실시' 로 쓴다.
4. 한국어로, 지정된 JSON 형식으로만 답한다."""


def write_report_text(detection, knowledge, part_info=''):
    user = f"""[부품 정보] {part_info or '없음'}
[검출 결과] {json.dumps(detection, ensure_ascii=False)}
[지식] {json.dumps(knowledge, ensure_ascii=False)}

다음 JSON 으로 답하라:
{{"summary": "판정 요약 1~2문장",
  "defects": [{{"type": "...", "description": "위치·크기 포함 특징 1~2문장"}}],
  "causes": ["원인 후보", ...],
  "actions": {{"immediate": "...", "prevent": "..."}}}}"""
    res = ollama.chat(model=MODEL, format='json', think=False,
                      messages=[{'role': 'system', 'content': SYSTEM},
                                {'role': 'user', 'content': user}],
                      options={'temperature': 0.2})
    return json.loads(res['message']['content'])
```
- `format='json'` 으로 형식을 강제하고, `temperature` 를 낮춰 매번 비슷한 문장이 나오게 한다.
- `think=False` 는 Qwen3 의 생각 과정 출력을 끈다 (속도 향상). 구버전 ollama 패키지에서 오류가 나면 이 인자를 지운다.

### 3-4. 한 번에 실행 (`agent/pipeline.py`)

```python
from agent.detect import detect
from agent.knowledge import lookup
from agent.writer import write_report_text


def run(image_path, domain='pcb', part_info='', save_dir='outputs'):
    det = detect(image_path, domain, save_dir)
    if det['verdict'] == 'normal':
        return {'detection': det, 'text': {'summary': '결함이 검출되지 않아 정상으로 판정했습니다.'}}
    kb = lookup(d['type'] for d in det['defects']) if domain == 'pcb' else []
    return {'detection': det, 'knowledge': kb, 'text': write_report_text(det, kb, part_info)}
```

### 3-5. 작업자 확인 화면 (`app.py`, Streamlit)

화면 구성 제안:
1. 사진 업로드, 도메인(PCB / 금속) 선택, 품번·공정 입력
2. 결과: 표시 이미지 + 판정 배지(정상 / 재검 / 불량) + 결함 표 (유형을 드롭다운으로 **수정 가능**)
3. Qwen 이 쓴 설명·원인·조치를 **편집 가능한 텍스트 상자**로 표시
4. [확정] 버튼 → 보고서(Word) 생성·다운로드, [오탐 기각] 버튼 → 정상 처리 + 재학습용으로 이미지 보관

실행: `streamlit run app.py`

### 3-6. 보고서 (`agent/report.py`)

`python-docx` 로 양식을 채운다: 제목, 일시·품번, 판정, 원본 사진 + 표시 이미지, 결함 표(유형·위치·크기·신뢰도), 특징 설명, 원인 후보, 조치, **작업자 확인란(이름·서명·수정 내용)**.
주최 측 [보고서 양식] 을 받으면 그 양식의 .docx 를 템플릿으로 읽어 칸만 채우는 방식으로 바꾼다.

## 5. 알려진 한계와 다음 개선 과제

| 과제 | 내용 |
|---|---|
| 금속 모델 지식베이스 없음 | Dark Spot, Fold, Oxidation, Porosity, Scratch, Stain 의 원인·조치 YAML 작성 필요 |
| PCB 정상 오탐률 미측정 | 실제 정상 보드 사진으로 기준값(0.25/0.5) 확인 |
| 금속 스크래치·산화·접힘 성능 낮음 | 라벨 검수, 고해상도 학습, 데이터 추가 |
| 실사진 도메인 차이 | 실제 촬영 사진에서 못 잡으면 그 사진을 라벨링해 추가 학습 (같은 원본의 증강본 추가는 효과 없었음) |
| 큰 사진의 작은 결함 | 사진을 잘라 추론(타일링)하거나 `imgsz=1280` |
| 대회 데이터 교체 | 주최 측 데이터 도착 시: `tools/` 스크립트로 검수·분할 → 재학습 → 클래스명에 맞춰 taxonomy YAML 교체 |
| 해커톤 도전 포인트 | 적은 샘플 학습(증강·Few-shot), 판정 근거 시각화(박스·마스크 + 신뢰도), 한국어·베트남어 보고서 |
