# 08. 작업 정리와 완성품 트리 (2026-10-21 기준)

지금까지 한 작업을 덩어리별로 정리하고, 완성하려는 시스템의 구조(트리)와 진행 상태를 적었다.
자세한 과정과 수치는 각 항목의 문서를 본다 (02 작업 기록, 03 성능 결과, 06 에이전트 구현 기록).

---

## 1. 환경 구축
- **노트북 세팅:** Python 가상환경, GPU용 PyTorch(CUDA 12.8), Ultralytics(YOLO), 설치 확인 `check_setup.py` — docs/04
- **LLM 실행 환경:** Ollama 0.40.6 + Qwen3 8B (4비트 양자화, GPU 약 5.6GB). 인터넷 없이 동작
- **하드웨어:** RTX 5060 노트북 GPU 8GB 하나에 YOLO 와 Qwen 을 함께 올린다
- **시연 실행:** `launch_demo.ps1` 이 Ollama·서버를 자동으로 켠다. 바탕화면 바로가기 3개 (대시보드 · 채팅 · 실시간 검사)

## 2. 모델 제작
| 모델 | 한 일 | 결과 |
|---|---|---|
| **PCB 결함 검출** (YOLO11s, 8종) | 데이터 9,666장의 누수(같은 원본 조각이 학습·평가에 섞임) 발견 → 원본 단위 재분할 → 학습 | test mAP50 **0.886**, P 0.911, R 0.868 |
| PCB v3 (추가 데이터) | 증강 데이터 추가 재학습 | mAP50 0.875 로 하락 → **미채택** |
| **금속 표면 분할** (YOLO11s-seg, 6종) | 부품 단위 재분할, 부품 전체 'Normal' 라벨 제거로 정상 사진 244장 확보 | 사진 단위 판정 정확도 **92.7%**, mask mAP50 0.564 |
| **휴대폰 표면 분할** (YOLO11s-seg, 3종, Izumi 학습) | Izumi 브랜치에서 모델을 가져와 우리 데이터로 검증 | 완벽 검출 비율: 기름 97% · 스크래치 92% · 얼룩 74% |

- 평가 자료: 혼동 행렬 엑셀(영어, `results/confusion_matrix_test.xlsx`), 케이스별 우수 사례(`results/*/showcase/`)

## 3. 모델 연계 에이전트 (보고서 에이전트)
- **파이프라인** (`agent/pipeline.py`): 사진 → 검출(`detect.py`) → 판정 → 지식 조회(`knowledge.py`) → 문장 → 작업자 확인 → 보고서 → 검사 대장
- **판정 규칙 (코드 고정):** 신뢰도 0.25 미만 무시 / 0.25~0.5 의심 / 0.5 이상 이상. 유형별 예외 (치명 유형은 기준을 낮춤, 휴대폰 스크래치·얼룩은 최대 의심 등)
- **지식 파일 (YAML, 도메인별 3개):** 결함 이름(한·베·영), 심각도, 원인 후보, 조치
- **부가 기능:** 큰 사진 타일링(PCB), 금속 부품 단위 판정(여러 방향 사진), 대기함 일괄 처리, 오탐 기각 → 재학습용 샘플 보관
- **검사 대장:** jsonl 원본 + 엑셀(영어, 썸네일) + 날짜별 md. 여러 화면이 동시에 써도 깨지지 않게 잠금

## 4. LLM 연계
- **보고서 문장** (`writer.py`): 검출 결과와 지식만 근거로 주고 Qwen 은 요약·특징·원인·조치 문장만 쓴다. 원인 목록 자체는 지식 파일 원문
- **상담 에이전트** (`chat.py`): 열린 검사 결과에 대한 질의응답, "이렇게 고쳐줘" → 바꿀 문장 제안 → [적용]을 눌러야 반영
- **언어 제어:** 한·베·영 출력 규칙, 베트남어 용어집, 다른 언어가 섞이지 않게 마지막에 다시 지시
- **설정:** 생각 모드 끔, temperature 0.2~0.3, JSON 응답

## 5. 보고서
- **이상 → 부적합 보고서 (NCR):** 5W2H 문제 기술, 증거 사진, 긴급 조치, 처리 결정, 원인 후보, 시정·재발 방지, 8D 연계(치명·복합 결함이면 8D 권고), 승인란
- **의심 → 재검사 의뢰서 (Hold):** 다음 공정 투입 금지, 재검사 항목, 합격 → Hold 해제 / 불합격 → NCR
- 저장 전 미리보기, 3개 언어, Word(.docx)

## 6. 작업자 화면
- **대시보드형** (`app.py`): 입력 → 결과·결함 표·문장 → 오른쪽 대화창, 왼쪽 검사 대장
- **채팅형** (`app_chat.py`): 대화 중심 + 오른쪽 작업 패널(보고서 / 편집·확정)
- **공통:** 한·베·영 전환, 화면 안내 투어(언어 먼저), 질문 안내 상자, 아이콘, 톱니바퀴 로딩 표시, 시연 모드
- 검사 대상: PCB · 금속 부품 · 휴대폰 표면

## 7. 실시간 검사
- **가상 컨베이어 영상**
  - PCB: 결함 80장 + 정상 14장 (결함 자리를 같은 기판의 깨끗한 부분으로 복사해 정상 기판 생성), 약 3분 — `tools/make_conveyor_video.py`
  - 액정(휴대폰 표면): 모델이 다 맞힌 test 사진 60장 + 진짜 정상 19장, 약 2.6분 — `tools/make_phone_video.py`
- **영상 서버** (`live/server.py`): 카메라·영상을 여는 곳은 하나. 매 프레임 YOLO 미리보기 → 센싱 구역에서 제품당 한 번 판정 → 박스·도장 → 스트림.
  라인 종류(`--line pcb|phone`)에 따라 모델·센싱 구역 크기·제품 찾는 방식이 바뀐다.
- **에이전트 연결:** 보고 에이전트(대기열, 밀리면 AI 문장 없이 먼저 기록), 라인 감시 에이전트(연속 불량·같은 위치/유형 반복·불량률)
- **화면:** 실시간 검사 화면(8505), 전용 뷰어(8506, 프로젝터용)
- **성능:** 약 30fps, 프레임당 10~16ms
- **정답 대조 (확인용, 화면에는 `?eval=1` 일 때만):**

| 라인 | 제품 판정 | 결함 단위 F1 |
|---|---|---|
| PCB (94개) | 97.9% (정상 기판 2개 의심 오탐) | 0.997 |
| 액정 (79개) | 100% | 0.978 |

- **샘플 자료:** 액정 라인에서 판정·결함이 모두 맞은 결과 케이스별 4장 — `tools/collect_live_samples.py` (데이터 라이선스 확인 전이라 공개 저장소에는 사진을 올리지 않음)

## 완성품 트리
✅ 완료 · 🔶 일부 · ⬜ 남음

```
부품 불량 검사 AI 에이전트 시스템
├─ 입력
│  ├─ ✅ 사진 (예시 · 업로드 · 대기함 일괄)
│  ├─ 실시간 라인 (가상 컨베이어)
│  │  ├─ ✅ PCB 라인
│  │  ├─ ✅ 액정(휴대폰 표면) 라인
│  │  ├─ ⬜ 금속 라인
│  │  └─ ⬜ 혼합 라인 (3종 무작위 투입)
│  └─ 🔶 웹캠 입력 (코드만 있고 시험 안 함)
├─ 분배 에이전트 (자동 분류 · 라우터)      ⬜ Izumi 브랜치에 있음, 미연결
├─ 검출 모델
│  ├─ ✅ PCB (YOLO11s)
│  ├─ ✅ 금속 (YOLO11s-seg)
│  └─ ✅ 휴대폰 표면 (YOLO11s-seg, Izumi)
├─ 판정 규칙 (코드)                       🔶 동작함, 기준값은 초안 (고객 기준서로 교체 필요)
├─ 지식
│  ├─ ✅ 지식 파일 (YAML, 3종)
│  └─ 🔶 RAG (Izumi 브랜치, 미연결)
├─ 에이전트
│  ├─ ✅ 보고서 에이전트 (검출 → 판정 → 지식 → Qwen 문장)
│  ├─ 🔶 상담 에이전트 (질의응답 ✅ · 검사 이력 조회 ⬜ Izumi 브랜치)
│  └─ 🔶 라인 감시 에이전트 (PCB · 액정 라인)
├─ 보고서
│  ├─ ✅ 부적합 보고서 NCR (8D 연계)
│  └─ ✅ 재검사 의뢰서 (Hold)
├─ 기록
│  ├─ ✅ 검사 대장 (엑셀 · md · 동시 기록 잠금)
│  └─ ⬜ 담당자 알림 (Izumi 브랜치)
├─ 화면
│  ├─ ✅ 대시보드 · ✅ 채팅 (한·베·영, 투어, 검사 대상 3종)
│  ├─ ✅ 실시간 검사 · 전용 뷰어 (PCB · 액정)
│  └─ ⬜ 외부 공유 링크 (Cloudflare 터널)
└─ 자료
   ├─ ✅ GitHub (코드 · PCB 영상 Release · 이 문서)
   ├─ 🔶 발표 슬라이드 (실시간 검사 · 휴대폰 모델 내용 없음)
   ├─ ✅ 회의록 2회
   └─ ⬜ 라이선스 정리 (휴대폰 데이터)
```

## 남은 과제 (우선순위 제안)
1. 금속 라인 영상과 실시간 라인
2. 혼합 라인 + 분배 에이전트(라우터) — Izumi 브랜치에서 라우터만 가져오기 (패키지 3개 설치)
3. Izumi 브랜치 나머지(RAG·이력 조회·알림) 검토 후 합치기, 휴대폰 데이터 라이선스 정리
4. 발표 슬라이드에 실시간 검사·휴대폰 모델 추가
5. 외부 공유 링크(필요 시)
